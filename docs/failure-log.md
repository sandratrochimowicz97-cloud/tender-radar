# Failure log

Every real failure while building and running the assistant. Only things that actually happened.

| Date | What broke | Why | Fix | Prevented since by |
|---|---|---|---|---|
| 2026-10-29 | n8n could not connect to Postgres: "Connection refused" with host `localhost` | On Windows, n8n can resolve `localhost` to the IPv6 address `::1`, while Postgres is published only on the IPv4 address `127.0.0.1` (localhost-only by design) | Host set to `127.0.0.1` | README option B tells users to use `127.0.0.1` if `localhost` fails |
| 2026-11-03 | First TED run: 192 of 283 kept notices saved with no deadline | Only the tender deadline (`deadline-receipt-tender-date-lot`, BT-131) was requested. Notices that first ask firms to apply (restricted procedures, competitions) put their first deadline in a separate field, the deadline for requests to participate (`deadline-receipt-request-date-lot`, BT-1311), per TED's [search field list](https://docs.ted.europa.eu/ODS/latest/reuse/field-list.html) | Fetch step requests both fields and keeps the earliest date, the date the practice must act by. A missing deadline is shown as "check notice" and does not change the recommendation | Each run reports how many kept notices have no deadline. Re-run 2026-11-03: 0 of 171 without a deadline |
| 2026-11-03 | First TED run kept engineering, civil-engineering and construction-works notices | The query matches a notice if *any* of its CPV codes is architectural. Many engineering and works notices list an architectural code as a secondary code | Fetch step (plain code) keeps a notice only if its main CPV code (`main-classification-proc`, BT-262, per the same field list) starts with 712 (architectural) or 714 (urban planning, landscape) | Each run reports how many notices were dropped for this reason. Re-run 2026-11-03: 112 dropped, 171 kept |
| 2026-11-03 | First TED run kept notices whose deadline had already passed (e.g. a deadline of 26 Oct in a run on 3 Nov) | The catch-up window starts at the last successful run, or 14 days back on the first run, so it includes notices that have already closed | Fetch step (plain code) drops a notice once its earliest deadline has passed. That is usually the request to participate; after it, the practice can no longer take part | Each run reports how many notices were dropped as closed. Re-run 2026-11-03: 5 closed, 166 kept |
| 2026-11-03 | `start-n8n.bat` closed straight away: "Task Broker's port 5679 is already in use" | n8n starts an internal helper (task broker) on port 5679 by default. Another n8n on the same machine already used it | `N8N_RUNNERS_BROKER_PORT=5681` set in `start-n8n.bat`; the window now stays open after n8n stops, so the error can be read | README troubleshooting row |
| 2026-11-04 | First Excel run stopped at *Collect partner decisions*: "expects the node's input data to contain a binary file" | On the first run there is no Excel file yet. The file step returned nothing (not an error), so the step after it failed, and the check treated that as a real read problem | The check now looks at the file step first: no file means first run, and the file is created. A file that exists but can't be read still stops the run | Tested for first run, file open in Excel, unreadable file, and a file with decisions |
| 2026-11-04 | First assessment run: some tenders marked GO although they asked for more than the practice has (e.g. EUR 3m liability insurance against EUR 2.5m), and GO on references for any kind of project (a nature-mapping contract matched all 8 school, housing and landscape references) | The model put insurance amounts in "other requirements", which code does not compare; and references asked for as "comparable" without a typology matched every project | Instruction: insurance and turnover amounts always go to their own fields, with currency. Code: any open requirement that names an amount blocks GO; references count only for a known typology; GO needs a typology the practice pursues | Rules version in Settings: all open tenders were assessed again under the new rules |
| 2026-11-05 | First MCP run on a Windows machine: every deadline shown one day early (a tender due 6 Nov listed as due 5 Nov) | The `pg` library turns a SQL `date` into a JavaScript time at local midnight; converting it back to text in UTC moved it to the day before on a machine east of UTC. Tests had run on a UTC machine, where it can't show | Dates are passed through as plain text (`pg.types.setTypeParser(1082, ...)`) | The smoke test, run on the machine where the server is used |
| 2026-11-05 | The secrets hook (`protect-secrets.js`) did not run: a command naming `n8n-data` was not blocked, although the script blocks it when run by hand | `.claude/settings.json` passed the script path in an `args` field next to `"command": "node"`; the hook did not fire in a real session. Exact cause not confirmed; the documented form puts the whole command line in `command` | `"command": "node \"$CLAUDE_PROJECT_DIR/.claude/hooks/protect-secrets.js\""` | Re-test after any change to the hook settings: a command naming `n8n-data` must be blocked |
